# Private Instance Deployment Guide

This guide walks through deploying a private, access-controlled instance of the PACTA TRISK dashboard for a specific bank engagement.

## Prerequisites

- A GitHub account with access to create private repositories
- A Streamlit Community Cloud account (free tier supports 1 private app)
- The client's pipeline snapshot (generated by running the refresh pipeline on the client's normalized loanbook)

## Step-by-Step Recipe

### 1. Create a Private Repository

```bash
# Clone the main repo
git clone https://github.com/tah-allotrope/pacta-trisk.git pacta-trisk-<bank-slug>
cd pacta-trisk-<bank-slug>

# Remove the remote and create a new private repo
git remote remove origin
# Create a new private repo on GitHub named pacta-trisk-<bank-slug>
git remote add origin https://github.com/tah-allotrope/pacta-trisk-<bank-slug>.git
git push -u origin main
```

### 2. Replace the Dashboard Snapshot

Point the app at the client-specific snapshot with `PACTATRISK_SNAPSHOT_DIR`
(no per-bank repository copy):

```bash
# Option A (deployments with env-var control): leave dashboard/data/ untouched
PACTATRISK_SNAPSHOT_DIR=/path/to/client/snapshot python -m streamlit run dashboard/app.py

# Option B (deployments with no env-var control, e.g. Streamlit Cloud):
# copy the client snapshot over the synthetic one
cp -r /path/to/client/snapshot/* dashboard/data/
git add dashboard/data
git commit -m "chore: replace snapshot with client data for <bank-slug>"
git push
```

Either way the client snapshot is generated by the refresh pipeline on the
operator machine. On an operator machine with several client snapshots,
`ENGAGEMENT_PICKER=1` adds a sidebar picker (operator use only, never on a
multi-user deployment).

### 3. Deploy on Streamlit Community Cloud

1. Go to [share.streamlit.io](https://share.streamlit.io)
2. Click "New app"
3. Select the private repository `pacta-trisk-<bank-slug>`
4. Set branch to `main`
5. Set main file path to `dashboard/app.py`
6. Click "Deploy"

**Note:** Streamlit Community Cloud free tier supports 1 private app. If you already have a private app deployed, you'll need to delete it first or upgrade to a paid plan.

### 4. Configure Secrets

In the Streamlit Cloud app settings, go to **Settings → Secrets** and add:

```toml
DEMO_PASSWORD = "<generate-a-strong-password-at-least-16-chars>"
```

**Do NOT set** `PILOT_ANALYTICS_ENDPOINT` — private instances should not send analytics pings with client-scoped data.

**Do NOT set** `BYOL_INTAKE`, `OUTPUTS_LAYER`, or `TRISK_LIVE_RERUN` — these require an R runtime which Streamlit Cloud does not provide.

### 5. Smoke Checklist

- [ ] Open the app URL in an incognito window → password prompt appears
- [ ] Enter the correct password → landing page renders
- [ ] "Data as of" badge shows the client snapshot date (not "unknown")
- [ ] All 5 pages render: Landing, PACTA Alignment, TRISK Risk, Reports, Methodology
- [ ] No synthetic-data banner references (the client snapshot should not include synthetic disclaimers if the data is real)

### 6. Teardown at Engagement End

When the engagement concludes:

1. Delete the Streamlit Cloud app (Settings → Delete app)
2. Delete the private GitHub repository (Settings → Delete repository)
3. Confirm deletion per the retention clause in the engagement contract
4. Remove any local copies of the client snapshot from the operator machine

## Security Caveats

**This is an access curtain, not real security.** The password gate:
- Uses a shared password (no per-user auth)
- Has no rate limiting
- Stores authentication in session state (cleared on browser close)
- Is appropriate for aggregated synthetic/anonymized views only

For engagements involving sensitive real data, the client's own infrastructure (VPN, SSO, audit logging) should be the security boundary. This private-instance recipe is for convenience during the pilot/demo phase.
